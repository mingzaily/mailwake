# 邮箱监听

[English](monitoring.md) · [文档目录](README.zh-CN.md)

## 邮箱兼容性

允许IMAP与应用密码的Gmail账户沿通用邮箱字段配置：`imap.gmail.com`、端口`993`、完整账户地址与应用密码。Google应用密码要求两步验证，部分账户策略会限制该能力；修改Google账户密码会撤销已有应用密码，更新已保存的IMAP凭据后重新连接。要求见[Google应用密码说明](https://support.google.com/accounts/answer/185833?hl=en)。

Gmail Label作为IMAP文件夹发现，Core保留可选路径，包括嵌套Label与`[Gmail]`、`[GoogleMail]`系统目录，并过滤`\Noselect`。每个订阅Folder有独立UID游标与事件身份；同一邮件出现在两个订阅Label时可以产生两条Folder通知。新订阅建立基线，重连沿原游标补查并应用既有24小时过滤规则。

网易邮箱（163.com、126.com、yeah.net）需要使用**授权码**作为 IMAP 密码。服务器声明支持 ID 时，Core 会在登录后、发现和打开文件夹前自动发送 [RFC 2971 ID 命令](https://www.rfc-editor.org/rfc/rfc2971)，仅包含 `name=Mailwake`、构建版本号、`vendor=Mailwake` 和 `support-url=https://github.com/mingzaily/mailwake`。ID 命令被拒绝时记录一条调试日志并继续；超时或传输中断时按正常策略重连。

连接复用登录后的能力列表判断 ID 和 IDLE。go-imap beta.8 在登录完成后异步清除旧能力缓存，Core 先用 NOOP 等待该处理完成，再读取自动刷新的能力列表。登录响应已携带能力列表时直接复用；打开文件夹后省去额外的 CAPABILITY 命令。

文件夹被拒且带有效 IMAP 响应码时，返回 `last_error.code=imap_folder_rejected` 和 `params.response_code`，例如 `UNAVAILABLE`、`NONEXISTENT`。响应码仅保留 `A-Z`、`0-9`、`-`、`/`，最多 32 字符；本地化提示与诊断使用过滤后的码，省略服务端原始文字。服务端未提供码或过滤后为空时返回 `imap_folder_open_failed`，省略响应码参数。
## 行为说明

| 场景 | 行为 |
| --- | --- |
| 订阅文件夹 | 以打开文件夹时的 UIDNEXT 为基线，跳过已有邮件 |
| 新邮件到达 | 读取 UID、发件人、主题和内部日期，生成通知任务；主题与发件人名称支持 GBK、Big5、Shift_JIS 等编码 |
| 进入文件夹的邮件接收时间早于 24 小时 | 推进进度、不生成通知，例如手动整理进来的旧邮件或长时间停机后的积压 |
| 实时 Folder 支持 IDLE | 等待变化提示，并每 60 秒补查一次，`mode=idle` |
| 实时 Folder 不支持 IDLE | 每 60 秒检查一次，`mode=poll` |
| 定时 Folder（`5m` / `15m`） | 启动或订阅变更后立即检查，再按周期检查，`mode=scheduled` |
| 连接中断或命令超时 | 指数退避后重连，从保存的进度继续 |
| 邮件服务器拒绝登录凭据 | 状态显示“需要重新认证”，每 30 分钟重试一次，避免账户被锁定；通过设置 API 更新凭据后立即生效 |
| 同一连接运行满 30 分钟 | 关闭并重新打开文件夹，重新读取 UIDVALIDITY，不计为故障 |
| 重启 | 补查停机期间仍在文件夹中、接收时间在 24 小时内的新邮件 |
| 取消订阅 | 停止对应文件夹监听；已经入队的通知继续处理 |
| 修改邮箱连接配置 | 锁外测试后只替换该邮箱的监听，其他邮箱继续运行 |
| 只改显示名称 | 按当前 revision 保存，更新后续通知的名称，保持连接与进度 |
| 只改 Folder 检查方式 | 在线交接监听并保留进度，其他实时 Folder 保持连接 |
| 删除邮箱 | 停止该邮箱监听，删除其配置、订阅与进度；已入队通知继续投递 |
| 再次订阅 | 重新建立基线，只通知之后到达的邮件 |
| UIDVALIDITY 变化 | 建立新基线、跳过已有邮件，并显示诊断提示 |
| 通知请求失败 | 默认结束本次任务，记录结果 |
| 配置自动重试 | 对网络错误、HTTP 429/5xx 等临时失败按配置重试 |
| 手动重试 | 管理界面把失败任务重新入队，开始新一轮请求 |

建连超时 15 秒；登录、能力查询、ID、文件夹查询、补查及 IDLE 进入和退出各受 30 秒命令超时约束，超时会关闭连接并重连。补查先发送 NOOP 让服务器同步文件夹变化，再用 `UID SEARCH` 查找进度之后的新邮件，元数据每批最多 500 封，Native 验证码识别每批最多 8 封。Native 正文逐封解析，每批成功后保存进度；不对已选中的文件夹使用 STATUS。实时连接持续运行至少一分钟并完成一次等待与补查后，退避恢复为初始值；定时检查在整轮成功后恢复初始退避。

同一邮箱的全部定时 Folder 在一轮到期检查中共用一个连接，按 next_check 最早优先、同时间按名称排序，顺序分批补查，结束后关闭连接。每轮最多登录一次；下次时间从检查完成时起算。连接失败采用指数退避，认证失败后该邮箱的定时检查暂停 30 分钟。单个 Folder 被拒但连接仍可用时，安排该 Folder 重试并继续检查其他到期项。

每个邮箱的订阅独立校验版本，先写入 SQLite 再调整该邮箱监听。未变更的监听保持连接，移除的监听退出后才启动替换项。保存订阅时在同一事务中清除新加入文件夹的旧进度。保存成功表示订阅已持久化，实际连接状态通过 `/api/v1/status` 确认。取消全部订阅会持久化为空列表。

`delivery.retry_count` 默认 **0**，每个任务自动请求最多一次；**2** 表示首次请求加最多两次自动重试，允许 0–9。退避从约 5 秒开始，最长 30 分钟；服务端 `Retry-After` 最长等待 24 小时，超过时结束本轮并记录失败；等待时间持久化。凭据错误等永久失败直接结束，修正配置后可手动重试。尚未开始的任务使用投递时配置的通道；已开始的原生任务沿用原生通道。

请求次数在发送前持久化。默认配置下，进程中断后会结束已经开始的请求，不会自动再次发送；如果恰好在计数落盘和网络发送之间退出，该次请求可能尚未发出。Mailwake 以请求尝试作为投递边界，记录通道响应；设备展示由通知通道负责。

文件夹进度和通知任务在同一个 SQLite 事务中保存。事件命名空间包含稳定邮箱 ID 与身份（host、port、username），再结合文件夹、UIDVALIDITY、UID 标识任务。两个邮箱的同名文件夹、相同 UID 产生不同事件。每个数据目录只运行一个 Core；邮箱 host、port 或 username 变化时只清理该邮箱进度并建立新基线，修改密码、显示名称或预算保留进度。其他邮箱的连接与进度保持不变，旧队列继续投递。

邮件由服务端规则直接归类时，订阅规则的目标文件夹即可。去重按文件夹进行：同一封邮件出现在两个已订阅文件夹中会产生两条通知。邮件若在两次检查之间进入后又离开文件夹，可能无法观测到。
## 隐私与数据

- 每个邮箱独立保存在 `mailbox:<id>` 配置项，完整配置项名称参与 AES-GCM 认证。邮箱和通道配置使用 AES-256-GCM 加密，随机 256 位密钥保存在数据目录的 `secret.key`（0600）。加密保护单独泄露的数据库文件或导出；能够读取完整目录和密钥的人仍可解密。请保护整个卷与备份；原密钥丢失后，加密配置无法恢复。
- 管理员密码使用带参数的 Argon2id 哈希；会话 ID、设置码、API Token 只保存哈希。API Token 完整值仅在创建响应中返回，设置码仅在启动日志的一行显示。设置响应、诊断和运行日志均省略凭据。
- IMAP 使用隐式 TLS（通常 993）并校验证书；所有通道使用 HTTPS，不跟随重定向，凭据不会被转发到其他主机。
- `delivery.preview=off`（默认）时，任务保存邮箱 ID、显示名称、邮件定位信息、文件夹和时间；始终省略邮件正文。
- 开启 `subject` 后，待处理和失败任务保存发件人、主题；Bark/Pushover 正文显示截断后的主题，Webhook 额外保留结构化发件人和主题。使用第三方通道时，通知内容会经过该服务。邮件正文始终留在邮箱。
- 通道接受请求后清除投递载荷，历史摘要保留邮箱 ID、投递时的显示名称、文件夹和标题，省略发件人和正文。标题遵循预览策略（原生通道始终记录）；第三方通道的 `off` 预览仅让新记录省略标题，已有历史标题保持原样。成功记录保留约 7 天，失败记录保留 30 天，每小时分批清理，摘要随记录删除。
- 文件权限、数据卷、磁盘加密和备份由部署环境管理，SQLite 使用普通本地存储。
